# Rule 1 - 驗證必須逐任務對應

- 驗證命令必須覆蓋每個目標任務直接修改或新增的行為。
- 優先執行與目標任務最近的單元測試、整合測試、lint 或 typecheck。
- 無法執行自動驗證時，必須記錄原因與手動檢查證據。
- 不得只因為檔案已修改就判定任務完成。

## Good Example

- 批次中每個任務都有自己的驗證證據。

```text
Task: T019 implement scoreGuess
Validation: npm test -- one-a-two-b.test.ts
Result: PASS

Task: T024 implement game screen
Validation: npm run typecheck
Result: PASS
```

## Bad Example

- 批次只跑了一個總命令，卻沒有判斷每個任務是否被覆蓋。

```text
Tasks: T019, T024
Validation: npm test
Result: PASS
Missing: no evidence that T024 UI path was checked
```

# Rule 2 - 失敗必須在任務範圍內修正後重驗

- 驗證失敗時，必須先判斷失敗是否屬於目標任務範圍。
- 屬於目標任務範圍的失敗必須修正後重新執行驗證。
- 不得在驗證仍失敗時將目標任務打勾。

## Good Example

- 第一次驗證失敗，修正目標函式後重新驗證通過。

```text
Run 1: FAIL one-a-two-b.test.ts
Fix: adjust B-count duplicate handling
Run 2: PASS one-a-two-b.test.ts
Checkbox: [X]
```

## Bad Example

- 驗證失敗後仍打勾。

```text
Run 1: FAIL one-a-two-b.test.ts
Checkbox: [X]
Reason: implementation mostly done
```

# Rule 3 - 打勾必須逐任務最後寫入

- 只有在目標任務驗證通過或已有明確手動完成證據後，才可以把 checkbox 從 `[ ]` 改成 `[X]`。
- 打勾必須只更新已通過驗證的任務行。
- 同一批次中可以打勾多個任務，但每個任務都必須有各自的通過證據。
- 不得因為同批次中某個任務通過，就替其他未驗證或失敗的任務打勾。
- 打勾後必須重新讀取 `tasks.md`，確認目標任務狀態與下一個未完成任務。

## Good Example

- 同批次中只打勾已完成且已驗證的任務。

```markdown
- [X] T019 [P] [US1] 在 backend/src/game/one-a-two-b.ts 實作 scoreGuess
- [X] T024 [P] [US1] 在 frontend/src/screens/game.ts 實作對局畫面
- [ ] T020 [US1] 在 backend/src/game/room-state-machine.ts 實作 submit_guess
```

## Bad Example

- T019 通過後連同未驗證的 T020 一起打勾。

```markdown
- [X] T019 [P] [US1] 在 backend/src/game/one-a-two-b.ts 實作 scoreGuess
- [X] T020 [US1] 在 backend/src/game/room-state-machine.ts 實作 submit_guess
```

# Rule 4 - 範圍外失敗必須停止修正

- 不屬於目標任務範圍的既有失敗必須寫入回覆作為阻塞。
- 範圍外失敗不得進入修正循環。
- 範圍外失敗的任務不得打勾。
- 同批次中已通過驗證的其他任務仍必須依各自證據打勾。

## Good Example

- 既有前端測試失敗不屬於 T019，因此只記錄阻塞並保留 T019 的通過結果。

```text
Task: T019 implement scoreGuess
Result: PASS
Checkbox: [X]

External failure: frontend/catalog.test.ts
Action: record blocker and stop fixing
Checkbox for unrelated tasks: unchanged
```

## Bad Example

- 為了讓整個測試命令變綠，去修改範圍外的前端測試。

```text
Task: T019 implement scoreGuess
External failure: frontend/catalog.test.ts
Action: edit frontend/catalog.test.ts until npm test passes
```
