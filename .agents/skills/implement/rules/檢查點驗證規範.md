# Rule 1 - 跨越 Checkpoint 前必須已有有效通過紀錄

- 選擇某個 Checkpoint 之後的任務前，該 Checkpoint 必須已有有效通過紀錄。
- 通過紀錄無效或缺少時，必須先驗證該 Checkpoint，不得選擇 Checkpoint 之後的任務。
- 本次批次若把 Checkpoint 之前的最後未完成任務做完，必須在打勾後驗證該 Checkpoint。
- 不得用「相關任務都已打勾」代替 Checkpoint 驗證。

## Good Example

- Foundational 任務都已打勾，但 Checkpoint 尚未通過，因此本次只驗證 Checkpoint。

```markdown
## Phase 2: Foundational
- [X] T016 建立路由器骨架

**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用

## Phase 3: User Story 1
- [ ] T017 [US1] 撰寫測試

本次目標批次：驗證 Phase 2 Checkpoint
未選任務：T017
```

## Bad Example

- 沒有 Checkpoint 通過紀錄就直接選擇下一個 Phase 的任務。

```markdown
**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用

本次目標批次：T017
```

# Rule 2 - 通過紀錄必須寫在 Checkpoint 下方

- 驗證通過時，必須在該 Checkpoint 下一行寫入 `**Checkpoint status**: PASS`。
- 驗證失敗時不得寫入 PASS。
- 同一 Checkpoint 已有 PASS 時，不得重複寫入第二行狀態。
- 通過紀錄只代表該 Checkpoint 原文描述的結果通過。

## Good Example

- 驗證通過後，狀態行緊接在 Checkpoint 下方。

```markdown
**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用
**Checkpoint status**: PASS
```

## Bad Example

- 驗證失敗仍寫入通過紀錄。

```markdown
**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用
**Checkpoint status**: PASS
驗證結果：session 建立失敗
```

# Rule 3 - 通過紀錄必須與前置任務一致

- Checkpoint 之前的任務仍有未完成項時，既有 PASS 必須視為失效並移除。
- 前置任務全部完成且 PASS 存在時，後續執行可以直接選擇 Checkpoint 之後的任務。
- 移除失效 PASS 後，必須重新驗證才能再寫入 PASS。
- 不得保留與目前任務勾選狀態矛盾的 PASS。

## Good Example

- 前置任務被改回未完成，因此移除 PASS。

```markdown
- [ ] T016 建立路由器骨架

**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用
```

## Bad Example

- 前置任務未完成，卻保留 PASS 並繼續後面的任務。

```markdown
- [ ] T016 建立路由器骨架

**Checkpoint**: 訪客 session、SQLite、HTTP／WS 骨架可用
**Checkpoint status**: PASS

本次目標批次：T017
```

# Rule 4 - Checkpoint 失敗必須在所屬任務範圍內修正後重驗

- `阻塞` 不是空白時，不得驗證或修正 Checkpoint。
- `阻塞` 為空白、本次失敗原因與 `implement-run.md` 的 `失敗原因` 不同，且該 Checkpoint 之前的任務描述或 References 已指出涵蓋此次失敗行為的檔案時，必須修正該檔案。
- 不得修改該 Checkpoint 之後的任務所指向的檔案。
- 不得把已打勾任務改回未完成。
- 寫入修正後必須重新驗證同一個 Checkpoint。
- 重新驗證通過前不得寫入 PASS，也不得選擇該 Checkpoint 之後的任務。
- `阻塞` 為空白，且本次失敗原因與 `失敗原因` 相同或沒有可寫入的修正時，不得再寫入修正，必須把 `阻塞` 與 `恢復條件` 寫入 `implement-run.md`。

## Good Example

- session 建立失敗後，修正 Checkpoint 前的 session 檔案並重新驗證通過。

```text
Checkpoint: 訪客 session 可用
Result: FAIL session 建立失敗
Fix: backend/src/session.ts 補上建立 session
Re-verify: PASS
```

## Bad Example

- session 建立失敗後沒有修正所屬檔案，直接結束本次執行。

```text
Checkpoint: 訪客 session 可用
Result: FAIL session 建立失敗
Action: 結束本次執行
```
