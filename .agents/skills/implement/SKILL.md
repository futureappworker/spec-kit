# SOP

## Phase 1: 讀取輸入與定位任務清單

1. Read 讀取使用者輸入並取得目標 feature 目錄、指定任務 ID、是否允許略過 checklist，以及本次執行邊界。
2. Think 決定目標 `tasks.md` 路徑為指定 feature 目錄或目前功能目錄中的任務清單。
3. Read 讀取目標 `tasks.md` 並取得任務格式、Phase、端點小節、未完成任務、References、Checkpoint 與 Dependencies 區段。
4. Read 讀取同目錄 `plan.md` 並取得原始碼落地位置、系統介面盤點、技術棧與驗證線索。

## Phase 2: 執行前檢查

1. Read 若 feature 目錄存在 `checklists/`，讀取 checklist 檔案並取得勾選狀態。
2. Think 若存在未完成 checklist 且使用者未允許略過，決定本次狀態為等待使用者確認。
3. Write 若本次狀態為等待使用者確認，將 checklist 狀態與是否繼續的問題寫入回覆 Artifact，並停止本次 SOP 的所有後續步驟。
4. Read 讀取專案根目錄的套件、測試、lint 與格式化設定檔並取得可用驗證命令。

## Phase 3: 選擇可執行任務批次

1. Read [任務選擇規範](rules/任務選擇規範.md)並取得任務選擇、Phase gate 與 Checkpoint 要求。
2. Read [平行執行規範](rules/平行執行規範.md)並取得平行批次准入、序列化與逐任務證據要求。
3. Read [檢查點驗證規範](rules/檢查點驗證規範.md)並取得 Checkpoint 通過紀錄、失效條件與驗證時機要求。
4. Think 依已載入規範決定第一個可執行的未完成任務。
5. Think 若使用者指定任務 ID，依已載入規範判斷該任務是否可執行。
6. Think 依已載入規範決定本次目標是實作批次，或只驗證尚未通過的 Checkpoint。
7. Think 若本次目標是實作批次，依已載入規範決定可安全平行執行的任務與不可跨越邊界。

## Phase 4: 載入任務最小上下文

1. Read 若本次目標是實作批次，讀取 [任務上下文載入規範](rules/任務上下文載入規範.md)並取得 References、端點邊界與原始碼讀取要求。
2. Read 若本次目標是實作批次，依已載入規範逐任務讀取每個任務正下方列出的 References 位址並取得直接實作或斷言的契約部位。
3. Read 若本次目標是實作批次，依已載入規範逐任務讀取任務描述中的目標檔案、相鄰測試檔與必要原始碼檔案並取得既有實作模式。
4. Think 若本次目標是實作批次，決定每個已選任務的最小變更範圍、同檔案衝突風險、測試先行要求與完成判定。

## Phase 5: 執行任務批次

1. Read 若本次目標是實作批次，讀取 [任務執行規範](rules/任務執行規範.md)並取得變更範圍、測試任務與實作任務要求。
2. Write 若本次目標是實作批次且存在測試任務，依已載入規範逐任務將對應使用者可觀察行為、錯誤路徑或契約斷言寫入目標測試檔。
3. Delegate 若本次目標是實作批次且存在測試任務，依已載入規範使用專案既有測試指令逐任務取得新寫入測試的失敗結果。
4. Write 若本次目標是實作批次且存在實作任務，依已載入規範逐任務將滿足該任務 References 與描述的最小原始碼或文件變更寫入目標檔案。
5. Think 若本次目標是實作批次，依已載入規範確認本次變更仍停留在已選任務批次邊界內。

## Phase 6: 驗證與打勾

1. Read 若本次目標是實作批次，讀取 [驗證與打勾規範](rules/驗證與打勾規範.md)並取得驗證、失敗修正、範圍外停止與 checkbox 更新要求。
2. Think 若本次目標是實作批次，依已載入規範決定每個已選任務的最小驗證命令、關聯測試、lint 檢查與手動檢查條件。
3. Delegate 若本次目標是實作批次，依已載入規範使用專案既有測試、lint 或格式檢查指令執行驗證並取得結果。
4. Read 若本次目標是實作批次，讀取驗證輸出與編輯器診斷並取得失敗原因或通過證據。
5. Think 若本次目標是實作批次，依已載入規範把每個失敗分成目標任務範圍內或範圍外阻塞。
6. Write 若失敗屬於範圍外阻塞，依已載入規範將阻塞證據寫入回覆 Artifact，不修正該問題，也不為該任務打勾。
7. Write 若失敗屬於目標任務範圍，依已載入規範修正該任務範圍內的測試、原始碼或文件問題並回到本 Phase 第 2 步。
8. Write 若某個任務驗證通過，依已載入規範將 `tasks.md` 中該任務的 checkbox 從 `[ ]` 更新為 `[X]`。

## Phase 7: 驗證 Checkpoint

1. Think 依已載入規範決定要移除的失效通過紀錄，以及本次必須驗證的 Checkpoint。
2. Write 依已載入規範移除 `tasks.md` 中已失效的 Checkpoint 通過紀錄。
3. Delegate 若本次必須驗證 Checkpoint，使用對應該 Checkpoint 原文的驗證命令或手動檢查並取得結果。
4. Read 若已執行 Checkpoint 驗證，讀取驗證輸出並取得通過或失敗證據。
5. Write 若 Checkpoint 驗證通過，依已載入規範把通過紀錄寫入 `tasks.md` 的對應 Checkpoint。
6. Write 若 Checkpoint 驗證失敗，依已載入規範將失敗證據寫入回覆 Artifact。

## Phase 8: 回報並結束本次執行

1. Read 重新讀取 `tasks.md` 中本次目標批次、Checkpoint 通過紀錄與下一個未完成任務。
2. Think 決定本次完成的任務、驗證結果、Checkpoint 結果、阻塞事項與下一次執行可選擇的任務。
3. Write 將完成的任務 ID、修改摘要、驗證結果、是否已打勾、Checkpoint 結果、下一次建議任務與阻塞事項寫入回覆 Artifact，並結束本次執行。
