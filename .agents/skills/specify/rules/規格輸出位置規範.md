# Rule 1 - 已指定路徑優先

- 使用者已給出輸出路徑時，必須使用該路徑作為 Feature Specification 的輸出檔案。
- 使用者未給出輸出路徑時，不得把回覆當作規格檔案的輸出位置。

## Good Example

- 使用者指定了檔案路徑，因此規格寫入該路徑，而不是改寫到預設目錄。

```text
使用者指定：docs/game-spec.md
輸出檔案：docs/game-spec.md
```

## Bad Example

- 使用者已經指定路徑，卻改把規格寫進預設的 specs 目錄。

```text
使用者指定：docs/game-spec.md
輸出檔案：specs/001-online-game/spec.md
```

# Rule 2 - 未指定路徑時的預設檔案

- 使用者未給出輸出路徑時，必須使用 `specs/<NNN>-<feature-slug>/spec.md`。
- `<NNN>` 必須是三位數字。
- `<NNN>` 必須等於 `specs/` 底下、目錄名以三位數字加連字號開頭的既有最大編號加一。
- `specs/` 底下沒有符合該格式的目錄時，`<NNN>` 必須是 `001`。
- 決定 `<NNN>` 時，必須忽略目錄名不是三位數字開頭的項目。
- `<feature-slug>` 必須是由本次功能名稱得出的小寫英文短名，單字之間使用連字號。
- 預設檔案名稱必須是 `spec.md`。

## Good Example

- `specs/plan` 不是三位數字開頭，不佔用編號，因此下一號是 `001`，slug 使用小寫英文短名。

```text
既有目錄：specs/plan
功能名稱：線上雙人 1A2B
輸出檔案：specs/001-online-1a2b/spec.md
```

## Bad Example

- 把 `specs/plan` 當成已占用的編號，因此錯用 `002`。

```text
既有目錄：specs/plan
功能名稱：線上雙人 1A2B
輸出檔案：specs/002-online-1a2b/spec.md
```

# Rule 3 - 回覆只報告檔案路徑

- 規格正文必須寫入已決定的輸出檔案。
- 回覆必須包含該輸出檔案路徑。
- 不得只把完整 Feature Specification 留在回覆，而不寫入輸出檔案。

## Good Example

- 規格寫入檔案，回覆只指出路徑，讓後續步驟可以讀取同一個檔案。

```text
輸出檔案：specs/001-online-1a2b/spec.md
回覆：規格已寫入 specs/001-online-1a2b/spec.md
```

## Bad Example

- 回覆貼上完整規格，但沒有產生規格檔案。

```text
輸出檔案：無
回覆：# Feature Specification: 線上雙人 1A2B
```
