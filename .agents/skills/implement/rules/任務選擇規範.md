# Rule 1 - 每次只選一個安全任務批次

- 每一個安全任務批次必須先選出 `tasks.md` 中第一個前置條件已滿足的未完成任務作為批次起點。
- 可以把與批次起點可安全平行的未完成任務加入同一批次。

## Good Example

- 以第一個可執行任務為批次起點，加入明確可平行的任務。

```markdown
- [X] T001 建立目錄
- [ ] T002 初始化 backend 專案
- [ ] T003 [P] 初始化 frontend 專案

Parallel Opportunities: T002 與 T003 可平行
本次目標批次：T002、T003
```

## Bad Example

- 跳過第一個可執行任務，只挑較想做的任務。

```markdown
- [X] T001 建立目錄
- [ ] T002 初始化 backend 專案
- [ ] T003 [P] 初始化 frontend 專案

本次目標批次：T003
```

# Rule 2 - Phase 必須阻擋後續任務

- Phase 1 必須在 Phase 2 之前完成。
- Phase 2 完成前不得選擇任何 User Story 任務。
- Polish Phase 必須在欲交付的使用者故事任務完成後才能選擇。

## Good Example

- Foundational 還有未完成任務，因此不選 User Story 任務。

```markdown
## Phase 2: Foundational
- [ ] T010 建立 session 驗證

## Phase 3: User Story 1
- [ ] T017 [US1] 撰寫測試

本次目標任務：T010
```

## Bad Example

- Foundational 未完成卻跳到 User Story，破壞 phase gate。

```markdown
## Phase 2: Foundational
- [ ] T010 建立 session 驗證

## Phase 3: User Story 1
- [ ] T017 [US1] 撰寫測試

本次目標任務：T017
```

# Rule 3 - 批次完成後必須繼續直到任務清單完成

- 一個安全任務批次及其必要的 Checkpoint 驗證完成後，必須立刻開始下一個前置條件已滿足的未完成任務批次。
- 批次之間不得等待使用者確認是否繼續。
- 使用者指定任務 ID 時，該 ID 不得作為本次執行的結束邊界，也不得取代第一個前置條件已滿足的未完成任務。
- 必須在 `tasks.md` 沒有未完成任務，且每個已到達的 Checkpoint 都有有效通過紀錄時，結束本次執行。
- `implement-run.md` 的 `阻塞` 不是空白時，必須結束本次執行，不得選擇下一個批次。

## Good Example

- T017 完成後仍有未完成任務，因此立刻開始下一個批次。

```markdown
本次批次：T017
T017 Checkbox: [X]
未完成任務：T018
下一個批次：T018
```

## Bad Example

- T017 完成後仍有未完成任務，卻停下來等待使用者確認是否繼續。

```markdown
本次批次：T017
T017 Checkbox: [X]
未完成任務：T018
回覆：是否繼續 T018？
```
