# Rule 1 - 全完成才把規格標成 Implemented

- `implement-run.md` 的 `阻塞` 為空白、`tasks.md` 沒有未完成任務，且每個已到達的 Checkpoint 都有有效通過紀錄時，必須把該 feature 的 `spec.md` 狀態列改為 `Implemented`。
- 已到達的 Checkpoint 是指該 Checkpoint 之前的任務都已完成。
- 有效通過紀錄是緊接在該 Checkpoint 下方的 `**Checkpoint status**: PASS`。
- `tasks.md` 沒有 Checkpoint 時，Checkpoint 條件視為成立。
- 狀態列已經是 `Implemented` 時，必須保持 `Implemented`。
- 寫入時不得修改 `spec.md` 的其他內容。
- 目標 `spec.md` 不存在時，不得建立 `spec.md`。

## Good Example

- 任務與 Checkpoint 都完成，因此只改狀態列。

```markdown
阻塞：
未完成任務：無
Checkpoint status：已到達的 Checkpoint 皆為 PASS
**狀態 ( Status )**：Implemented
```

## Bad Example

- 完成條件成立，卻連需求本文一起改寫。

```markdown
阻塞：
未完成任務：無
Checkpoint status：已到達的 Checkpoint 皆為 PASS
**狀態 ( Status )**：Implemented
**FR-US1-001**: 已改寫的需求本文
```

# Rule 2 - 未全完成不得改規格狀態

- `阻塞` 不是空白、`tasks.md` 仍有未完成任務，或任一已到達的 Checkpoint 沒有有效通過紀錄時，不得修改 `spec.md`。

## Good Example

- 還有未完成任務，因此狀態維持原值。

```markdown
阻塞：
未完成任務：T029
**狀態 ( Status )**：Ready for Planning
```

## Bad Example

- 任務尚未完成，卻把規格標成已實作。

```markdown
阻塞：
未完成任務：T029
**狀態 ( Status )**：Implemented
```

# Rule 3 - 憲法停止寫入時不得改狀態

- 憲法停止寫入 `spec.md` 時，不得修改狀態列。
- 憲法停止寫入時，必須把拒絕原因寫入回覆。

## Good Example

- 憲法停止寫入，因此狀態維持原值，並在回覆說明原因。

```markdown
憲法 Rule：停止寫入 spec.md
**狀態 ( Status )**：Ready for Planning
回覆：拒絕更新規格狀態，因為憲法停止寫入 spec.md。
```

## Bad Example

- 憲法已停止寫入，卻仍把狀態改成已實作。

```markdown
憲法 Rule：停止寫入 spec.md
**狀態 ( Status )**：Implemented
回覆：規格狀態已更新為 Implemented。
```
