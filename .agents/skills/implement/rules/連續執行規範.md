# Rule 1 - 結束本次執行的條件

- 下一個執行位置必須是 Phase 4 第 4 步或 Phase 11。
- `implement-run.md` 的 `阻塞` 不是空白時，下一個執行位置必須是 Phase 11。
- `阻塞` 為空白，且 `tasks.md` 沒有未完成任務，且每個已到達的 Checkpoint 都有有效通過紀錄時，下一個執行位置必須是 Phase 11。
- 不符合上述 Phase 11 條件時，下一個執行位置必須是 Phase 4 第 4 步。
- 不得因 `STOP and VALIDATE` 進入 Phase 11。
- 批次之間不得等待使用者確認是否繼續。
- 結束回覆不得詢問使用者是否繼續。
- 使用者指定的任務 ID 不得作為本次執行的結束邊界。

## Good Example

- 任務都完成且 Checkpoint 都有 PASS，因此結束本次執行。

```markdown
阻塞：
未完成任務：無
已到達 Checkpoint：皆有有效 PASS
下一個執行位置：Phase 11
```

## Bad Example

- Phase 3 的 STOP and VALIDATE 已通過，仍有 T029，卻因此結束本次執行。

```markdown
阻塞：
STOP and VALIDATE：Phase 3 之後
Checkpoint status：Phase 3 PASS
未完成任務：T029
下一個執行位置：Phase 11
```

# Rule 2 - 交付說明不得單獨當成結束條件

- `tasks.md` 中的「MVP First」與「MVP 止於」必須只用來對應某一個 `STOP and VALIDATE`。
- 「MVP First」與「MVP 止於」不得單獨當成 Phase 11 的進入條件。
- 「MVP First」與「MVP 止於」不得寫入 `implement-run.md` 的 `阻塞` 或 `恢復條件`。
- 故事進行中且所屬 Checkpoint 尚未有有效通過紀錄時，不得結束本次執行。

## Good Example

- 只有 MVP 字樣、Checkpoint 尚未通過時，繼續下一批，不把交付說明寫進阻塞。

```markdown
Implementation Strategy：MVP First；MVP 止於 Phase 3
Checkpoint status：Phase 3 尚無 PASS
未完成任務：T028
阻塞：
下一個執行位置：Phase 4 第 4 步
```

## Bad Example

- 把 MVP 字樣寫進阻塞，並在 Checkpoint 尚未通過時結束。

```markdown
Implementation Strategy：MVP First；MVP 止於 Phase 3
Checkpoint status：Phase 3 尚無 PASS
未完成任務：T028
阻塞：MVP 止於 Phase 3
下一個執行位置：Phase 11
```

# Rule 3 - STOP and VALIDATE 通過後必須繼續

- `STOP and VALIDATE` 之前的任務都已完成，且該 Checkpoint 尚未有有效通過紀錄時，下一個執行位置必須是 Phase 4 第 4 步，且該批次必須驗證該 Checkpoint。
- 該 Checkpoint 已有有效通過紀錄，且其後仍有未完成任務時，下一個執行位置必須是 Phase 4 第 4 步，並做下一個未完成任務。
- 不得在 `STOP and VALIDATE` 結束本次執行。

## Good Example

- Phase 3 已通過，T029 尚未完成，因此繼續做 T029。

```markdown
STOP and VALIDATE：Phase 3 之後
Checkpoint status：Phase 3 PASS
未完成任務：T029
阻塞：
下一個執行位置：Phase 4 第 4 步
批次：T029
```

## Bad Example

- Phase 3 已通過，卻在 STOP and VALIDATE 結束，把 T029 留到下一次執行。

```markdown
STOP and VALIDATE：Phase 3 之後
Checkpoint status：Phase 3 PASS
未完成任務：T029
阻塞：
下一個執行位置：Phase 11
回覆：下一次 /implement 再從 T029 繼續
```
